# PingMe Now

Laravel 9–13 agent for the self-hosted PingMe monitoring hub. Requires PHP 8.1+.

## Installation

```bash
composer require michalkortas/pingme-now
php artisan pingme:install
```

`pingme:install` asks for the Hub URL and then the application token generated by the Hub. It verifies the connection, publishes backup scripts and immediately sends the first status.

For an automated installation:

```bash
php artisan pingme:install \
  --url=https://pingme.example.com \
  --token=pm_token_generated_by_hub
```

Manual status delivery:

```bash
php artisan pingme:now
```

The package automatically adds the command to Laravel Scheduler every minute. The host must run `php artisan schedule:run` from cron or `php artisan schedule:work`.

## Collected data

- Laravel, PHP, environment and hostname
- database and cache availability
- queue canary and failed jobs from the last 24 hours
- disk capacity/free space for configured paths
- ERROR+ log events with secret redaction and a local retry spool
- Composer and npm lockfile inventories

Optional configuration:

```dotenv
PINGME_DISK_PATHS=/var/www/html/storage,/backups
PINGME_QUEUE_CONNECTION=redis
PINGME_QUEUE=default
PINGME_SPOOL_MAX_BYTES=20971520
```

## External backups

The installer publishes scripts to `scripts/`. They use `PINGME_URL` and `PINGME_TOKEN` from the shell environment.

Debian/Docker scan:

```bash
scripts/pingme-backup.sh scan database /srv/backups/database
```

Debian/Docker wrapper reporting start, success/failure and final sizes:

```bash
scripts/pingme-backup.sh run database /srv/backups/database -- ./backup.sh
```

Windows CMD:

```bat
scripts\pingme-backup.bat scan database D:\Backups\database
scripts\pingme-backup.bat run database D:\Backups\database -- backup.cmd
```

The reports contain the oldest/newest backup time, file count, total size, newest file size, duration and result.
